# RBEL-CRM — notes for coding agents

Laravel 13 API + React/TypeScript SPA (Vite, same origin, Sanctum cookie auth). See README.md and docs/.

- Business rule: `policies.policy_owner_id` and `policies.policy_insured_id` are separate relationships. Never merge them into one person/client filter; every person-based filter, sort and analytic takes an explicit owner-or-insured role.
- Database is MySQL 8+ (dev: MySQL 9.1 on port 3306). Views and stored procedures live in `database/migrations/*_create_reporting_views_and_procedures.php`.
- Tests run on MySQL (`rbel_crm_demo_test`): `php artisan test`. Frontend: `npx tsc --noEmit`, `npm run build`.
- Validation goes in Form Requests, response shaping in API Resources, multi-step writes in `app/Services` inside `DB::transaction`.
- Models using the `Auditable` trait write audit_logs automatically; use `App\Support\AuditLogger::record()` for non-CRUD events.
- shadcn/ui components are in `resources/js/components/ui` (generated by the shadcn CLI; `components.json`).
